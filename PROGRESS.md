## Running the live probe

The Gemini key is at `~/.config/scholar-reader/gemini.key` (outside the repo, mode 600). `npm run probe` sends a fixture to a real provider and reports section alignment, bullet counts, over-length bullets by position, and whether results sections keep their figures:

```
npm run probe                                        # adam / gemini-dev, per-section, ~0.1c
npm run probe -- --fixture bert --provider gemini-prod   # whole-document, ~1c
```

`npm run probe` calls the adapter. `node tools/prod-check.mjs --fixture gpt3,bert` goes through the real router instead — consent refusal, one request, quota +1, progress timeline, cache-hit reopen — then the same quality report (`tools/probe-report.mjs`, which splits over-length bullets by third of the response). `--all` runs every fixture, ~17¢ on `gemini-prod`.

`tools/live-probe.mjs` and `tools/prod-check.mjs` are the only things that read that key path; neither prints it. The extension itself takes its key from settings into `storage.local` at step 14.

## Open issues

### ⚠️ Math symbols still render wrong in the pane — UNRESOLVED, parked 2026-09-12

The user reports `⊙` and `∝` (and earlier `𝜈`, `𝑎`, `𝑏`) still displaying wrongly on their own paper after three rounds of fixes. **Parked at their request; they will pick it up later.** The fixes made along the way are real improvements and stay, but none of them resolved the reported symptom.

**Ruled out, with the method — do not re-derive these:**
- *Not an unmapped glyph.* `node tools/probe-glyphs.mjs <pdf>` over three real astro-ph papers: `⊙` arrives as **U+2299**, the correct codepoint, 19/5/25 occurrences, zero private-use characters.
- *Not font coverage.* A render test screenshotted in headless Chrome shows **no boxes in any stack**, including bare `system-ui`; macOS supplies a last-resort face unaided. `fontTools` over all 583 installed faces confirms Apple Symbols, STIX Two Math and Arial Unicode MS each cover U+2299 and U+221D.
- *Not the flattening.* `extract/normalize.js` touches neither character — they are operators, not restyled letters, and are deliberately left alone.

**Shipped along the way (all verified, all kept):** math-alphanumeric flattening; Adobe private-use bracket pieces mapped to real delimiters; subscripts no longer stranded onto lines of their own; scripts rendered at their levels in the extraction panel; STIX Two Math leading the symbol fallbacks (measurably better glyphs — operators at text size on the text baseline rather than undersized and low).

**The gap, and it is the whole problem: every piece of evidence above comes from substitute papers, never the user's.** Two things were never established, and both change what the fix is:
1. **Which pane is wrong.** Assumed throughout to be the outline/extraction panel. Never confirmed. If it is the **PDF pane**, every CSS change above was aimed at the wrong target — that pane draws glyphs from the PDF's own embedded font programs onto canvas, and the suspects are `pdfview.js`'s `standardFontDataUrl`/`cMapUrl` wiring and pdf.js font loading, with nothing to do with the page's font stack.
2. **What "wrong" looks like.** An empty box, a box with hex digits, the wrong glyph, a correct glyph rendered badly, and a glyph in the wrong place are five different faults with five different causes. Each round of guessing here cost a full cycle.

**Next session, before changing any code — in this order:**
1. A screenshot of the failure, and which pane it is in.
2. `node tools/probe-glyphs.mjs <the user's own paper>` — one command, gives the raw codepoints pdf.js produced.
3. The extraction panel's **Unrenderable characters** block for that paper (added 2026-09-12; lists each codepoint and count, and is empty when there is nothing unmappable).

## Decisions & gotchas

- 2026-11-21 — **Claude Code keeps working after the answer; the bridge does not wait for it.** A text-mode `claude -p` makes a post-turn summary request after the reply (~1.6 s), then takes ~0.9 s more to exit. Nothing after the answer is for the reader, so the bridge resolves at `result` (structured) or at an `end_turn` `message_stop` (text) and SIGTERMs the child. Sessions are not persisted (`--no-session-persistence`), so stopping it loses nothing. `--bare` was not tried: its help says it skips keychain reads, which is where the subscription login lives on macOS.

- 2026-11-18 — **No serif in the outline: the user found it unreadable.** The first pass set the outline in Iowan Old Style with an italic TL;DR; the user rejected it on sight. The outline is back on the system sans, at 13.5px, with the TL;DR upright. Do not reintroduce a display or book face for the outline prose.
- 2026-11-18 — **Blue, not green and brass, and Inter bundled — both at the user's request.** `@fontsource-variable/inter` 5.3 (OFL-1.1) is a dependency; the build copies only the Latin, Latin Extended and Greek variable files (~150 KB together) plus the licence into `dist/fonts/`, declared in `viewer/fonts.css` with each subset's `unicode-range`, so a page downloads only the subsets it uses. Linked from the viewer and settings pages. The capture skeleton cannot use it (it lives in the publisher's origin under `default-src 'none'`) and falls back to the platform sans for its few seconds on screen. Checked in a browser: the Latin file reports `loaded` and the text renders in Inter. **Dark theme only is checked from here on, at the user's request; the light theme is not worth testing.**
- 2026-11-18 — **Save PDF uses a blob link, not `browser.downloads`.** The `downloads` permission would change the signed manifest's permission list and prompt on update, for no gain: an extension page may offer a blob with `download=` on its own. The bytes are `pdfDoc.getData()`, because `source.bytes` may already be detached by pdf.js's worker, and refetching would break the single-use publisher links that step 17 exists for.
- 2026-11-18 — **The capture skeleton's `TOKENS` mirror `theme.css`, and a test holds them together.** Any palette change has to edit `background/skeleton.js` as well; `capture.test.mjs` fails otherwise, which is how this redesign found it.
- 2026-11-18 — `viewer.js` is now 224 lines (5 added to wire the download). It still holds just the element table and boot order; the download logic itself lives in `download.js`.

- 2026-09-27 — **Zen containers partition an extension page's IndexedDB; the background's is not the tab's.** First live run of step 17: arXiv fell back to `timing (fetch)` with "no captured PDF for this tab". The reader tab's `cookieStoreId` was `firefox-container-2` (not private), and its `inbox` read empty while the background had stashed the entry — the token only reaches the URL after the stash's transaction completes. Fixed: the viewer asks the router (`{type: "capture", token}`) and the background reads its own store; `capture.test.mjs` fails if a viewer module imports `store/inbox`. **The same split very likely affects older code, unverified:** the viewer writes consent (`outline-pane.js` → `grantConsent`) and document records/reading position (`store/docs.js`) into *its* partition, while the router checks consent in the background's. In a container tab that fails safe — nothing is sent — but would re-show the confirm card after approval. Not fixed here; flagged as its own task. → Confirmed and fixed as step 18.

- 2026-09-11 — **Resolved (was the open question for step 7/13): `gemini-prod` keeps `strategy: "whole-document"`.** The original reason for it — a 20-requests-per-day cap — never existed, so the choice was re-argued from scratch against the eleven fixtures (mean paper 18 sections / ~13.2k est. tokens; `gpt3.json` the stress case at 32 sections / ~51k). `per-section` was recommended first, on three grounds, and two and a half of them did not survive scrutiny: (a) long-output degradation is modest, and everything structural about it is expressible in the JSON schema, which is constrained decoding rather than a request; (b) the index-misalignment hazard is fixable for a few lines — echo the title, keep using the index, treat a mismatch as malformed — so it is not a reason to pick a strategy; (c) cross-section context, which was the headline argument *for* whole-document, is close to worthless for bullets that CLAUDE.md requires to be extractive, since synthesis is exactly what the prompt forbids. - 2026-09-11 — **The title checksum, and why it is a correctness rule rather than a nicety.** SPEC originally said the adapter re-attaches `page`/`y` by index "rather than trusting the model to echo them". Index stays the source of truth, but the echo is now *required and compared*: a section-count or title mismatch is a malformed response per CLAUDE.md. Without it a dropped section silently shifts every later bullet onto the wrong scroll target, with nothing on screen to indicate it — and the amplifier is the cache: an outline is written under the cache key and thereafter served with **no confirmation card and zero network requests**, so a slip that is not caught at write time is permanent rather than a thing you re-roll. Hence the check runs before the cache write, not after. Per-paper draws are independent, so nothing accumulates across papers; what accumulates is bad entries that never expire.
