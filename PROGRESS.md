## Decisions & gotchas
- 2026-09-11 — Pushed to <https://github.com/notKivon/firefox-pdf-reader>, **public** by the user's explicit choice; `main` tracks `origin/main`. History was scanned blob-by-blob for `AIza…`/`sk-…`/`gho_…` before the first push and was clean. Consequence to keep in mind: a key committed here is world-readable and permanent, so it must be rotated rather than deleted. `check:secrets` only greps `dist/`, which is gitignored — it would not catch a key pasted into a source file.
- 2026-09-11 — Real Tier 1 limits, straight off the user's AI Studio page: `gemini-3.8-flash` 10,000 RPD / 1,000 RPM / 2M TPM; `gemini-3.5-flash-lite` 150,000 RPD / 4,000 RPM / 4M TPM. The 20-RPD free-tier figure this plan was built around was a placeholder and is off by ~500×.
- 2026-09-11 — **User preference: `gemini-3.8-flash` is the default provider.** `DEFAULT_PROVIDER_ID` is `gemini-prod`. Paid-tier pricing is $0.75/$3.75 per 1M in/out (promotional — it doubles to $1.50/$7.50 on 2027-01-01), which works out near 1.3¢ per paper. Quality on the paper actually being read outweighs that.
- 2026-09-11 — Because the default is now the production provider, **step 12 is no longer a switch**. What survives of it is the verification: confirm one request per paper and that streaming still fills the pane progressively.
- 2026-09-11 — **Open question for step 7/12:** `gemini-prod` keeps `strategy: "whole-document"`, but the reason for it is gone — that strategy was forced by a 20-requests-per-day cap that does not exist. At 10,000 RPD, `per-section` is affordable and fills the pane progressively. Left as specced deliberately rather than changed unasked; decide before writing the adapter, because strategy is part of the cache key and flipping it later invalidates every cached outline.
- 2026-09-11 — `limits` now carries `tpm` alongside `rpd`/`rpm`. For a whole-document request TPM is the limit that can actually be approached; RPD cannot be, at this volume. The adapter may ignore `tpm` but the number should not be lost.
- 2026-09-11 — A paid tier does not change the quota-day rule: Google's counters still roll at midnight US Pacific, so `store/quota.js` keys by the Pacific date string as planned.
- 2026-09-11 — `web/pdf_viewer.mjs` destructures `globalThis.pdfjsLib` **at module-evaluation time**, and `build/pdf.mjs` is what assigns that global. Importing the viewer directly would crash on a bundle-order coin flip, so `src/viewer/pdfjs.js` imports the core first and re-exports the viewer. Verified in the built bundle: the assignment sits ~3.5 kB ahead of the destructure.
- 2026-09-11 — pdf.js 6 decodes JPX/JBIG2 in WebAssembly, which MV3's default CSP forbids. `content_security_policy.extension_pages` now carries `'wasm-unsafe-eval'`. Without it, PDFs with JPEG2000 images fail to render.
- 2026-09-11 — `pdf.worker.mjs`, `cmaps/`, `standard_fonts/`, `wasm/`, `iccs/` and `web/images/` are **copied** into `dist/`, not bundled: the worker is spawned as `new Worker(src, {type:"module"})` and the rest are fetched at runtime. `pdf_viewer.css` and `images/` must stay siblings or its relative `url(images/…)` breaks.
- 2026-09-11 — The viewer fetches the PDF bytes itself (`credentials: "include"`) and hands `getDocument` a `Uint8Array` rather than a URL. Cookies reach paywalled publisher PDFs, and step 4 needs the raw bytes in hand for the sha256 identity anyway.
- 2026-09-11 — The redirect makes the browser request the PDF twice (main_frame, then the viewer's own fetch, normally served from the HTTP cache). The second request is not `main_frame`, so the interceptor cannot loop.
- 2026-09-11 — The `onHeadersReceived` listener registers **synchronously** at background top level; an event page that attaches a blocking listener inside an `await` can miss requests on wake-up. Consequence: the origin opt-out set is empty for the one tick before `storage.local` resolves.
- 2026-09-11 — `web-ext lint`'s 4 `UNSAFE_VAR_ASSIGNMENT` warnings (`innerHTML`, dynamic `import`) come from bundled pdf.js, not our code, and are warnings rather than errors. The Firefox-for-Android warning is still irrelevant; the target is desktop.
- 2026-09-11 — `pdf.worker.mjs.map` (5.9 MB) is copied too. Without it devtools 404s on every worker load, which buries real errors in the console the Zen check depends on. It is over half of `dist/`; step 14 should decide whether the packaged XPI drops sourcemaps.
- 2026-09-11 — Two console lines in Zen are Firefox privacy notices, not faults: fingerprinting protection masking `screen.availWidth` (pdf.js reads it for DPI in `display_utils.js`) and arxiv.org classified as a bounce tracker. Neither affects rendering; don't chase them next session.
- 2026-09-11 — Only HTTP 200 and 206 are intercepted. 3xx has no body yet and 204 never will, so redirecting either would strand the tab on an empty viewer.
- 2026-09-11 — Bundles are built as `iife`, not `esm`. An MV3 background script loads as a classic script unless the manifest opts into modules, and esbuild bundles everything into one file anyway, so the module plumbing buys nothing.
- 2026-09-11 — `check:secrets` fails on **key-shaped** matches (`AIza…`, `sk-` + 16 or more key characters) and only warns on a bare `sk-`. A bare-substring match would fire on ordinary words inside bundled pdf.js ("task-", "risk-") from step 2 on, which would make the gate useless. Gate tested by planting a dummy key in `dist/`: exit 1 with the key, exit 0 without.
- 2026-09-11 — `strict_min_version` is `140.0`, not 128: AMO now requires `browser_specific_settings.gecko.data_collection_permissions` (declared as `none`), which Firefox only understands from 140. Zen 1.22b on this machine is Gecko 155.0.1, so this costs nothing. The one remaining lint warning is about Firefox for Android and is irrelevant — the target is desktop.
- 2026-09-11 — `src/extract`, `src/model`, `src/store` and `src/settings` exist locally but are empty, so git does not track them yet; they appear in the commit for the step that first puts a file in them.
- 2026-09-07 — Tier 3 build: the Gemini API key is a real secret, and there are three external dependencies (Gemini, Ollama, AMO).
- 2026-09-07 — *(rationale partly superseded 2026-09-11 — the 20-RPD cap was never real; the structural point stands.)* Chunking strategy is a provider property, not a global constant. A 20-requests-per-day free tier would force `whole-document`; a per-token provider would prefer `per-section`. Callers must never loop over sections themselves or this leaks upward and makes provider swaps into refactors.
- 2026-09-07 — All provider calls happen in the background script. Extension background fetches for hosts in `host_permissions` bypass CORS; Gemini's endpoints do not reliably send CORS headers, so calling from the viewer page would fail.
- 2026-09-07 — *(rationale superseded 2026-09-11 — Tier 1, so no meaningful daily cap; the split still holds on token cost.)* Develop on `gemini-3.5-flash-lite`, ship on `gemini-3.8-flash`. Fixtures in `fixtures/` exist so prompts can be iterated without re-parsing PDFs.
- 2026-09-07 — Google's free-tier daily quota resets at midnight US Pacific, not local time, so the counter is keyed by the Pacific calendar date rather than a local one.
- 2026-09-07 — Zen cannot install unsigned extensions; `xpinstall.signatures.required` is locked in its default profile config with no Zen-side override. Development is `about:debugging` (temporary, lost on restart); permanent installation requires AMO unlisted signing.
- 2026-09-07 — Section extraction from two-column PDFs is the highest-risk part of this build. Steps 5 and 6 are deliberately separate and both end in a visible debug panel, so failures are diagnosable rather than mysterious.
